# CamperJS — Notes for AI Agents

Browser widget library for FEP-3b86 Activity Intents: it discovers which intents a visitor's home Fediverse server supports (WebFinger, with NodeInfo fallbacks) and wires "like/reply/follow from your own server" buttons into a host page. See [README.md](README.md) for the full picture.

- **This is a page widget, not an importable library.** The bundle self-executes `Camper.render()` at load and finds its UI by CSS class names. The public API surface is: the `camper-*` class names (`camper-intent-button`, `camper-form`, `camper-accounts`, `camper-loading`, `camper-account-name`, `camper-show-if-has-accounts`, and friends), the `data-intent` / `data-{placeholder}` / `data-max-accounts` attributes, the `camper-hide` CustomEvent, and the `camper` localStorage key. External template repos (e.g. qwertylicious `qwerty-article/head-social.html`, `qwerty-outbox/follow.html`) bind to these names, so renaming any of them breaks consumers silently.
- **dist/ and the Emissary resources copy are generated — never hand-edit either.** `npm start` runs esbuild (watch, minified ESM) from `src/*.ts` into [dist/](dist/), which is committed. `npm run 4emissary` runs esbuild (watch, un-minified) straight into `../emissary/_embed/templates/theme-global/resources/camperjs`, which requires the emissary repo checked out as a sibling and is the only sanctioned way files get into that resources folder. Consumers load the bundle from `/.themes/global/resources/camperjs/camper.js`. Both scripts are `--watch` processes that never exit; there is no one-shot build script, so to refresh outputs you run one, let it write, and stop it.
- **The `Camper` page-global contract only survives in the `4emissary` build.** Generated account rows embed inline `onclick="Camper.doIntent(...)"` / `Camper.removeAccount(...)` strings that resolve `Camper` at click time. That works because the un-minified build keeps the top-level `var Camper` name and consumers load it as a classic `<script src=... defer>` (no `type="module"`), which makes the declaration page-global. The minified `dist/` build renames `Camper`, and a `type="module"` script tag would scope it away — either one silently breaks the account-row buttons.
- **Nothing type-checks this code.** esbuild strips types without checking and `typescript` is not in devDependencies; the strict [tsconfig.json](tsconfig.json) governs only the editor and a manual `npx tsc`. Type errors ship silently, so run the compiler yourself before trusting a change.
- **src/as/ is a snapshot of conversations-mls's ActivityStreams wrappers, and it is partially dead here.** Only `actor.ts`, `object.ts`, `utils.ts`, and `vocab.ts` are reachable (via [src/camper.ts](src/camper.ts) importing `Actor`). `activity.ts`, `collection.ts`, and `document.ts` are unreachable from any `src/*.ts` entry point, and [src/as/activity.ts](src/as/activity.ts) imports `newId` from `../service/utils`, which does not exist in this repo — esbuild never sees it, but a whole-project `tsc` fails there. The maintained originals live in conversations-mls under `user-conversations/resources/app/src/as/`; prefer fixing shared behavior there.
- **The Go twin is `tools/camper` in the emissary repo.** Both implement the same FEP-3b86 discovery ladder: WebFinger `https://w3id.org/fep/3b86/*` rel links first, the OStatus `subscribe` link mapped into the follow intent next, then NodeInfo software sniffing with per-software hard-coded share URLs, all producing `{placeholder}` URL templates with `(close)` defaults for `on-success`/`on-cancel`. The Go side powers Emissary's own `/.intents/*` handlers and `base-intent` modal (which has its own hyperscript state under the localStorage key `accounts`, unrelated to this library's `camper` key); CamperJS is the client-side implementation for external pages. Keep the rel URIs and placeholder grammar in sync across both.
- **The `relation.toLowerCase()` in [src/intents.ts](src/intents.ts) is load-bearing.** Its switch matches lowercase rel URIs (`https://w3id.org/fep/3b86/follow`), but Emissary itself publishes them capitalized (`.../Follow`, via `camper.IntentType*` constants in emissary's `service/user.go`). Remove the lowercasing and interop with Emissary servers breaks.
- **Everything fetched is untrusted; interpolation into HTML goes through the guards in [src/utils.ts](src/utils.ts).** WebFinger, NodeInfo, and ActivityPub actor documents come from arbitrary user-typed servers. The account list is built with `innerHTML`, so every interpolated field is neutralized for its context: `safeAttr` for attribute values, `safeText` for element text, `safeURL` for the icon URL, and usernames travel via a `data-username` attribute rather than being concatenated into inline JS. Any new interpolation must use the same helpers for the same contexts.
- **Intent templates are remote-controlled URLs.** `doIntent` substitutes `{placeholder}` values with `encodeURIComponent` and then passes the template, published by the account's home server, to `window.open` with no scheme check (`safeURL` is not applied at that sink). Treat these templates as untrusted at every sink you add.
- **`guessProtocol` is the only http/https decision point.** WebFinger and NodeInfo URLs are built from it in [src/utils.ts](src/utils.ts); it returns `http://` solely for `localhost` and `127.0.0.1`. Extend it there rather than special-casing protocols at call sites.
- **Tests hit the live network.** The vitest suites (`src/*.test.js`, plain JS beside the sources) call real servers — mastodon.social, pixelfed.social, benpate.dev — so they fail offline and can flake on third-party changes; a failure there is not necessarily a code regression.
